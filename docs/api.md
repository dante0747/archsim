# HTTP API (v1)

Base path: `/api/v1`. JSON uses camelCase. Without sign-in (`ARCHSIM_AUTH_MODE=none`, the
default) the API is local and single-user: every request is the local owner of the `default`
workspace. With `ARCHSIM_AUTH_MODE=oauth` people sign in, and projects and runs belong to
workspaces they are members of (see [Sign-in, workspaces and tokens](#sign-in-workspaces-and-tokens)
and [SECURITY.md](../SECURITY.md)).

- OpenAPI document: `GET /api/v1/openapi.json`
- Interactive docs: `GET /api/v1/docs`
- Hosted, the API is reached through the web server: `https://<host>/api/v1/...`.

## Errors

Domain errors use one shape:

```json
{
  "detail": {
    "message": "Cannot simulate: Redis Cache can miss (hit ratio 80%) but nothing reads the data on a miss: ...",
    "issues": [
      {
        "severity": "error",
        "code": "cache.miss_unrouted",
        "message": "Redis Cache can miss (hit ratio 80%) but nothing reads the data on a miss: its 'miss' port is not connected and API Servers has no link set to 'Reads only on a cache miss'.",
        "nodeId": "cache",
        "edgeId": null,
        "path": null,
        "hint": "Cache-aside: give the service a link to the database with 'Reads only on a cache miss' on. Read-through: connect the cache's 'miss' port to the database."
      }
    ]
  }
}
```

| Status | When |
| --- | --- |
| 400 | Contradictory request (e.g. both `document` and `exampleId`). |
| 401 | Sign-in is on, and the request has no valid session cookie or API token (`WWW-Authenticate: Bearer`). |
| 403 | Your role in the workspace is too weak (a viewer editing), a cookie request without the right `X-ArchSim-CSRF` header, or an API token doing what only a signed-in person may. |
| 404 | Unknown project, run, example or workspace, **or one in a workspace you are not a member of** (the same answer, so ids reveal nothing). |
| 409 | Revision conflict on save; report requested for an unfinished run; comparing unfinished runs; a workspace's last owner leaving; a project past a workspace's project limit. |
| 413 | Request body larger than `ARCHSIM_MAX_BODY_BYTES`. |
| 422 | Document invalid (with `issues`), run too large, a calibration that cannot be done, or FastAPI request validation errors (FastAPI's standard `detail` list). |
| 429 | A rate limit (runs per hour, sign-in attempts, ...): wait the `Retry-After` seconds. |

| GET | `/projects/{id}` | Project with its document and `revision`. |

| DELETE | `/projects/{id}` | Deletes the project and its runs. `204`. |
| POST | `/projects/{id}/duplicate` | Copy as "Name (copy)". `201`. |
| GET | `/projects/{id}/export` | The document as a download (`Content-Disposition: attachment`). |

Lists and new projects use the request's workspace: `?workspace=<id>` or the
`X-ArchSim-Workspace` header, else your personal workspace, else `default`. A project or run
asked for by id uses its own workspace: viewers read, editors change, create, simulate and
delete, and anyone without a role there gets 404.

Saving accepts documents that are *schema-valid* even if graph validation fails (for example a
dangling cache miss port), so work in progress can be stored. Simulation requires a fully valid
document. Schema-invalid documents (unknown keys, out-of-range link settings, wrong
`schemaVersion`) are rejected with `422`. The project name is authoritative and is copied into
`document.metadata.name`.

## Runs

| Method | Path | Description |
| --- | --- | --- |
| POST | `/projects/{id}/runs` | Body `{scenarioId?, label?, document?, seeds?, mode?}`. Validates, then enqueues. `202` with the run. `document` simulates unsaved edits; it is stored with the run. `seeds` (1-10, default 1) above 1 starts a seed group: one run per seed from the document's seed (base) to base + seeds - 1, all of one stored document, each with `groupId` and `seedIndex`; the answer is the first run. Seed and mode are stored with each run. |
| POST | `/projects/{id}/runs/batch` | Body `{scenarioIds: [..], document?}` (1-10 entries; `null` = base document). Validates all before enqueueing any. `202` with a list. |
| GET | `/projects/{id}/runs` | Recent runs (newest first, up to `ARCHSIM_RUN_HISTORY_LIMIT`, default 200), without reports. |
| GET | `/runs/{runId}` | Status, `progress` (0-1), `error`, seed, digests, and a small `summary` once finished. Poll this. |
| GET | `/runs/{runId}/report` | Full report (`409` unless `succeeded`). See below. |
| GET | `/runs/{runId}/input` | The exact document submitted for the run (re-importable). |
| POST | `/runs/{runId}/cancel` | Cancels a queued run immediately. A running one is stopped by the worker holding it, on any instance, within about 2 s (its next heartbeat; at once when that worker is in the same process); one still going `ARCHSIM_CANCEL_GRACE_SECONDS` (10 s) later is killed. The response shows `cancelled`, or `running` while the cancel is on its way. |
| POST | `/runs/{runId}/rerun` | Re-simulates the stored input with the same scenario, seed (a seed group's run keeps its own) and mode. Response has `reproducesRunId`; compare `resultDigest` values. `202`. |
| GET | `/run-groups/{groupId}` | A seed group: `kind`, `baseSeed`, `size`, `mode`, `scenarioId`, `label`, `status` (`running`, then `succeeded`, `partial` or `failed`), its `runs` by seed, and `summary` from the engine's `summarize_seeds` against the objectives of the document the runs used: `met`/`missed`/`undecided` of `finished`, `verdict` (`holds`, `fails`, `borderline` when the runs disagree, or null), `confidenceCap` (`medium` when borderline), `latencyMs.p50/p95/p99`, `successRate` and `throughputRps` ranges (`{min, max, median}`), and `text` ("Meets the objectives in 4 of 5 runs · p95 98–131 ms (median 104) · seeds 42–46"). | DELETE | `/runs/{runId}` | Cancels if active, then deletes. `204`. |

Run `status`: `queued`, `running`, `succeeded`, `failed`, `cancelled`. A failed run has
`error.message` and, for document problems, `error.issues`. `progress` is read from the
database, where the worker simulating the run writes it at most once a second, so every API
instance reports the same value.

### Background runs and several instances

Runs are queued in the database; workers take them. By default `archsim-api serve` contains a
worker (`ARCHSIM_EMBEDDED_WORKER=true`), so one command runs everything. Each run simulates in a
process of its own (`ARCHSIM_RUNNER=process`), up to `ARCHSIM_MAX_CONCURRENT_RUNS` at once
(default: CPU count - 1).

- **Restarts.** An API or worker that stops normally (Ctrl+C, SIGTERM) gives its runs back to the
  queue, and the next worker simulates them again from the start. One that dies without warning
  (killed, out of memory, host lost) stops renewing its runs' leases; after
  `ARCHSIM_LEASE_SECONDS` (30 s) another worker, or the same API after a restart, requeues them.
  A run whose worker stops twice is `failed` with "The simulation worker stopped
  unexpectedly…".
- **A crashed simulation** (its process ran out of memory or was killed) fails only that run,
  with the same message; the worker and its other runs carry on.
- **Deadline.** A run still going `ARCHSIM_MAX_WALL_SECONDS` + 30 s after it started is killed and
  `failed`, even if the simulation stopped checking its limits.
- **Several instances.** With PostgreSQL, any number of API instances and workers can share one
  database: workers claim runs with `FOR UPDATE SKIP LOCKED`, and cancel requests reach the
  worker holding a run wherever it is. Run extra workers with `archsim-api worker --slots N`
  (`docker compose --profile workers up --scale worker=2`), and set
  `ARCHSIM_EMBEDDED_WORKER=false` on API instances that should only serve HTTP. Hosts need
  synchronised clocks (NTP): leases compare their times. SQLite works for several processes on
  one machine only.
- **Migrations** take a PostgreSQL advisory lock, so instances starting together migrate one at
  a time. `archsim-api migrate` (the Compose `migrate` service) migrates once and exits; then
  set `ARCHSIM_AUTO_MIGRATE=false` on the instances.
- **Workers table.** `job_workers` lists each worker's latest heartbeat (every 2 s), slots and
  runs in flight; rows of workers gone for an hour are deleted.

## Sign-in, workspaces and tokens

`GET /auth/config` says which mode the server runs in (`none` or `oauth`) and its sign-in
providers. In `none` mode there is nothing to sign in to and nothing below needs a header.

**Signing in (browser).** `GET /auth/{github|google}/login?next=/path` redirects to the
provider (OAuth 2 with PKCE); the provider returns to `GET /auth/{provider}/callback`, which
sets the session cookie `__Host-archsim_session` (HttpOnly, Secure, SameSite=Lax) and the CSRF
cookie `__Host-archsim_csrf`, then redirects to `next` (a path on this site), or to
`/signin?error=state|denied|provider|disabled`. `POST /auth/logout` ends the session
(`?everywhere=true`: all of yours). Every request that changes something with the session
cookie must send `X-ArchSim-CSRF: <csrfToken>` (from `GET /auth/me` or the CSRF cookie), or it
gets 403.

**API tokens (CLI, CI, MCP).** Send `Authorization: Bearer asim_pat_...`; no cookie and no CSRF
header. A token acts as you, as a viewer if its scope is `read`, and only in its workspace if
it names one.

| Method | Path | Description |
| --- | --- | --- |
| GET | `/auth/config` | `{mode, providers}`. Public. |
| GET | `/auth/me` | `{mode, kind (local, session or token), user {id, name, email, avatarUrl}, workspaces [...], csrfToken}`. 401 when signed out. |
| GET | `/auth/{provider}/login` | Starts signing in (302 to the provider). `?next=` is where to land after. 429 after 30 starts per address in 10 minutes. |
| GET | `/auth/{provider}/callback` | The provider's return (302). |
| POST | `/auth/logout` | `204`; `?everywhere=true` ends every session of the account. |
| GET | `/workspaces` | Yours, with your `role`, `kind` (personal, team, sandbox) and limits (`maxConcurrentRuns`, `maxRunsPerHour`; null: the kind's). |
| POST | `/workspaces` | `{name}`: a team workspace you own. `201`. |
| GET, PATCH, DELETE | `/workspaces/{id}` | Read (members), rename (owners), delete a team workspace with all its projects and runs (owners; `default` and personal ones stay). |
| GET | `/workspaces/{id}/members` | Members with their roles. |
| PATCH, DELETE | `/workspaces/{id}/members/{userId}` | `{role}` (owners); remove someone (owners) or leave (yourself). A workspace keeps at least one owner (409). |

### Limits

With sign-in (or `ARCHSIM_RATE_LIMITS=true`) each workspace kind has limits, which a
workspace's own `maxConcurrentRuns`/`maxRunsPerHour` replace:

| Kind | Runs at once | Runs per hour | Largest run | Calibration replay | Projects | Seeds per group |
| --- | --- | --- | --- | --- | --- | --- |
| personal | 2 | 60 | the server's | 20 s | no limit | 5 |
| team | 4 | 300 | the server's | 20 s | no limit | 5 |
| sandbox | 1 | 20 | 200,000 requests, 20 s | 20 s | 5 | 5 |

Without sign-in a seed group may run 10 seeds (5 in a sandbox).

Runs at once are counted across every worker (a run waits in the queue until its workspace has
room; workers take each workspace's oldest run before anyone's second). A person may also start
300 runs an hour. Starting runs past a limit answers 429 with `Retry-After`, and a batch is
refused whole. The counters live in the database (`rate_limits`), so every API instance shares
them. Without sign-in the counters are off, and only sandboxes keep their other limits.

## Share links

A share link is a frozen, read-only copy of one finished run's results that anyone with the
link can open on the web app at `/r/<slug>`, without signing in. It holds the report without
request traces (calibration addresses hidden), the objectives from the run's input document,
the project name and that document (for "Open a copy"; the public answer leaves it out). It
does not change when the design does and stays when the run or project is deleted, until it
expires or is revoked. Slugs are 128 random bits in base62 (22 characters).

| Method | Path | Description |
| --- | --- | --- |
| POST | `/runs/{runId}/shares` | Editors: `{title?, expiresInDays? (default 30, at most 365; null: never)}`. `201` with `{id, slug, path: "/r/<slug>", url (when ARCHSIM_PUBLIC_URL is set), title, projectId, runId, createdAt, expiresAt, revokedAt, viewCount, resultDigest, reportVersion, status: active|expired|revoked}`. 409 unless the run succeeded. |
| GET | `/projects/{id}/shares` | Viewers: the project's links, newest first (revoked and expired ones included). |
| GET | `/shares` | Viewers: every link of the workspace (`?workspace=`), including those whose project was deleted. |
| DELETE | `/shares/{id}` | Editors: revoke at once (`204`); the stored copy is deleted. |
| GET | `/public/shares/{slug}` | No sign-in. `{slug, title, projectName, runLabel, scenarioName, createdAt, expiresAt, payloadVersion, reportVersion, resultDigest, objectives, report, canCopy}`; `?view=false` does not count a view (link previews). 404 alike for unknown, expired and revoked links; `Cache-Control: no-store`, `X-Robots-Tag: noindex`. With limits on, 60 answers a minute per address (429 with `Retry-After`). |
| POST | `/projects/from-share` | `{slug, name?}`: "Open a copy", a new project in the request's workspace (editors) from the shared design. `201` with the project. |

## Walkthrough with curl

```bash
API=http://127.0.0.1:8000/api/v1
wait_run() {  # poll until the run leaves queued/running
  while :; do
    s=$(curl -s "$API/runs/$1" | jq -r .status)
    [ "$s" = queued ] || [ "$s" = running ] || break
    sleep 1
  done
  echo "$1: $s"
}

# 1. Create a project from the starter example
PID=$(curl -s -X POST $API/projects -H 'content-type: application/json'   -d '{"exampleId": "cache-aside-starter"}' | jq -r .id)

# 2. Run two scenarios (returns immediately with status "queued")
A=$(curl -s -X POST $API/projects/$PID/runs -H 'content-type: application/json'   -d '{"scenarioId": "one-api-replica"}' | jq -r .id)
B=$(curl -s -X POST $API/projects/$PID/runs -H 'content-type: application/json'   -d '{"scenarioId": "three-api-replicas"}' | jq -r .id)

# 3. Poll until finished
wait_run $A; wait_run $B
curl -s $API/runs/$A | jq '{status, summary}'

# 4. Fetch the full report and its findings
curl -s $API/runs/$A/report | jq '.findings[] | {severity, title}'

# 5. Compare the two runs
curl -s "$API/compare?a=$A&b=$B" | jq '{inputDiff, explanations}'

# 6. Reproduce run A from its stored input and seed
R=$(curl -s -X POST $API/runs/$A/rerun | jq -r .id)
wait_run $R
curl -s $API/runs/$R | jq -r .resultDigest
curl -s $API/runs/$A | jq -r .resultDigest      # same value

# 7. Export and re-import
curl -s $API/projects/$PID/export -o starter.archsim.json
curl -s -X POST $API/projects/import -H 'content-type: application/json'   --data-binary @starter.archsim.json | jq '{id, name}'
```

## Stability

Paths are versioned (`/api/v1`). Breaking changes will go to `/api/v2`. Reports carry
`reportVersion` and documents carry `schemaVersion`.
